Vocabulary

Concepts

Terms you’ll see in the CLI, the report, and the planned metrics. Skim once; come back when a flag name stops making sense.

Cap height (optical)

The measured height of capital letters used as the anchor for the shared line box. Styles in one family share that height. Cap height and x-height are taken from the outlines. Stored sCapHeight and sxHeight are used only when those glyphs are missing, and a run writes the outline measurements back when the OS/2 table is version 2 or newer. An older table cannot store those fields, so they are left alone.

Core and outliers

The core styles set one planned typo/hhea box. A layer or swash whose ink runs past a sibling keeps that box and may clip. A script keeps the line box, and Win can grow around the swashes. --no-cluster skips that plan and uses outline extremes for the line box instead.

Typo / hhea vs Win

A default run makes the line box at least 130% of the em — 1300 units when the em is 1000 — and sets the line gap to 0. Baseline to baseline is then 1300. The before picture is a file that has not been through that run. The letters stay the same size, and the em stays 1000.

  • sTypoAscender / sTypoDescender / sTypoLineGap (OS/2) and matching hhea values define the line box many apps use when USE_TYPO_METRICS is on (OS/2 v4+).
  • usWinAscent / usWinDescent are clipping bounds. For the core styles, Win is the family’s outline extremes plus 2%, and it is never shorter than the line box. A layer or swash keeps that same Win and may clip. A script can widen Win.
  • The line gap is 0 unless you pass --line-gap. The same number is written to typo and hhea.

Where the line box comes from

The default plan follows the Google Fonts vertical metrics pattern, which SIL’s line-metrics guide calls the recommended strategy and which Glyphs documents as the Google strategy:

  • Typo and hhea are the same numbers. That is the line box.
  • Both line gaps are 0 unless you pass --line-gap. The box itself is the line spacing.
  • USE_TYPO_METRICS is set when OS/2 is version 4 or newer, so apps use that box instead of the Win values. An older table is not versioned here, and the run says the bit is not set.
  • Win is the clipping box. On the core styles it covers the outlines. A layer or swash keeps the core Win and may clip. A script can widen Win.
  • Styles in a family share one line box, so switching weight or italic does not change the line spacing of a paragraph.

Those guides set the line box by looking at the common letters and adjusting until the spacing looks right. ebrium replaces that step with a formula. The box starts at the measured cap height plus 25% of the em of headroom, with capitals centered in the box (ascender − cap = |descender|). If that span is under 130% of the em, it grows while staying centered. A measured descender can lower the bottom further. A tall accent does not raise the line box. Win on the core styles is the family’s outline extremes plus 2%, then raised again if the line box is taller, so the accent is covered there. If a descender needs more than 130%, the span is allowed to exceed the floor and the run flags it. A script can widen Win without pulling the family’s line box up to that extreme. A layer or swash keeps the core box, including Win, and the extra ink may clip.

The box is one set of numbers for the whole family, anchored on cap height. John Hudson’s note on Tamil and Latin and the SIL guide both point out that two scripts in one file often want different line spacing, and OpenType still stores a single set. ebrium does not add a second one.

Karsten Lücke’s font-metrics notes are the history behind the older rule that the typo span had to equal the em. That rule is no longer in the spec, and the default 130% floor does not follow it.

Span and line gap

--span (default 130) is the letter-span floor, as a percent of the em. 120 is tighter, 150 is looser. A measured descender can still lower that box. 0 leaves each file's ascender and descender as they are, and the line gap can still change. --line-gap (default 0) adds space between lines, also as a percent of the em. 5 is slightly looser.

Shared box

A run gives the core styles in a family one line box. --match "Family A,Family B" puts two families that do not already share a name onto that same box. probe shows how far each file’s stored ascender would move to match it. --no-cluster replaces that plan with one box from the family’s outline extremes.

What the outlines decide

The dashed edge is the span. The ochre line is the baseline. The teal lines represent x-height/cap height in relation to the baseline.

Calligraphy

The swashes cross the span. The word sits on the baseline.

layer

The shadow crosses the span

The face and the shadow share the span and the baseline. The shadow crosses the edge, and that ink may clip.

height

Short and tall, one baseline

One span, one baseline. The shorter lines mark each capital, so the shorter letters keep the tall one’s span.

unicase

Cap against x-height

One is unicase and one is not. The upper lines mark the cap and the x-height. Both sit on the baseline and share the span.

If the outlines miss a unicase and the name says unicase, the name is the fallback.

Family name

One family name is one line box. Caption, Display, and Subhead do not split it. A variable font stays with its own family name, separate from the statics. --match is how you pair names that should share a box anyway.

Checkpoint

A cache file is written. Every measuring run, including -n, writes .metrics_checkpoint.json in the current working directory. probe does not write one.

The file caches measurements and clusters. A font is measured again when its size or modification time changes, or when the options or the file list change. -y reuses that cache only while each file still matches.
