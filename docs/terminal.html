A run

Reading a run

A normal run measures the fonts, prints a plan, asks before it writes, then lists what changed in each file. The sample below is the line box drawing: an em of 1000, two styles, one shared box.

A normal run

Nothing here uses -v. The progress bar is only the measuring step. Files stay untouched until you answer the prompt.

Example-Bold.otf prints the same block when it started from the same numbers, and the tally counts both files. When the styles already differ, the before-numbers differ and the after-numbers still share one plan.

Labels

LabelWhat it’s doing
INFO Progress. Measuring, grouping, then the plan for each family.
MAJOR The line box is moving a lot. Read the next line before you answer the prompt. Moderate and Minimal are the quieter versions of this line.
INPUT Waiting for you. y writes the files in place. n stops the run. A blank answer asks again.
UPDATED What changed in that file: old value, then new value.
SUCCESS The tally. updated files were written, unchanged already matched the plan, errors could not be written.

The summary line

Family: Example (2 fonts) is the group that shared a family name. Core cluster: 2 fonts | UPM: 1000 means both styles were close enough in cap height to share one box. 1000 is the em. That number stays 1000.

UPM scaled by ~45.0% is how far the box edges moved, added together, as a percent of the em. The top edge moves 235 units (985 − 750) and the bottom edge moves 215 units (315 − 100). 235 + 215 = 450, and 450 is 45% of 1000. When styles in the group move by different amounts, the printed figure is their average.

increasing vertical height by 52.9% compares the new box with the old one. The box was 850 units tall (750 + 100) and is now 1300 (985 + 315). 1300 is 52.9% taller than 850. That 1300 is the default span floor: 130% of the em. The line gap is left out of that height.

linegap set to 0 removes the warm band. Baseline-to-baseline distance is the box plus that gap: 850 + 600 = 1450 before, and 1300 + 0 = 1300 after.

Word on the summaryMovement, as a percent of the em
Minimal Normalization Under 2%
Moderate Normalization At least 2% and below 8%
Major Normalization 8% or more

Under about 0.1%, or when the values already match, the run says no changes are needed.

What changed in the file

Above-baseline and below-baseline in the drawing are stored twice, once in OS/2 and once in hhea, and ebrium writes both copies together. Below-baseline is stored as a negative number: 100 below the baseline is -100, which is why the descenders hang out of the old box.

FieldIn the drawing
sTypoAscender, hhea ascent Top of the line box. 750 → 985. The capitals are 670, centered in the 1300 box, so 985 is above the baseline and 315 is below.
sTypoDescender, hhea descent Bottom of the line box. −100 → −315. The old 100 is shorter than the descenders, so they hang out. Together with 985, the new box is the 1300-unit default.
sTypoLineGap, hhea lineGap The gap between boxes. 600 → 0.
fsSelection (USE_TYPO_METRICS) Tells apps to use the typo line box for line spacing. On OS/2 version 4 or newer, ebrium turns that bit on. The line is absent when it was already set, and on older OS/2 tables.
usWinAscent, usWinDescent The clipping box: how far drawing may go before it is cut off. Ascent is above the baseline. Descent is below it and stored as a positive number. In this example they move out to the new box, 985 / 315, so the letters are not clipped.
vertical span Top plus bottom, with the line gap left out: 850 → 1300. +45.0% UPM is that 450-unit change divided by the em of 1000 — the same 45% as the summary, scored against the em again.

If you add -v or -vv

-v adds the measured cap height to the cluster line. For this drawing the capitals are 670 units, so the line gains (cap height ≈ 670/1000 = 0.670). That is the size of the letters. It is a separate number from the line box.

-vv adds lines marked DEBUG. They name the step that is running: sorting styles into the cluster, building the shared plan, then checking that the clipping box covers the line box. The plan is the same without them.

Preview first. -n prints the same file list with a dry-run marker and does not write. probe is a different printout — measured metrics and family pull, with no writes. See Reading probe.
