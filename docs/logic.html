Pipeline

How it thinks

The subcommand picks the grouping strategy. Everything after that follows the same four stages.

  1. Measure Cap height, x-height, ascenders, descenders, the tallest accented capital, and glyph bounds — normalized by each font’s UPM.
  2. Separate Core styles set the line box. Effect and script cuts inherit it. A peer group that mixes Caption, Display, Subhead, or Small Text is split into one box per size. A layered or color stack is stamped with one shared box. Skipped under individual. --no-cluster uses outline extremes instead.
  3. Plan Center capitals in the line box, grow to the letter-height floor while staying centered, then raise a side only when a measured accent or descender needs it. Win is the outline extremes plus 2%. The matching typo and hhea, a zero line gap, and Win as the clipping box follow the Google Fonts pattern. See Concepts.
  4. Apply Write metrics in place (unless -n). Enable USE_TYPO_METRICS when OS/2 ≥ 4. Zero line gaps. probe does not write.

Grouping strategies

SubcommandGroupingLine box
individual None — one font at a time One file; nothing shared
family By family name Shared centered box; --no-cluster uses outline extremes
superfamily Merge families sharing a name prefix Same box across the merge; optical sizes still split
probe — Read-only metrics tables; no write

Line box modes

The default, auto, is already one centered line box. The other modes replace that plan:

ModeBehavior
autoShared centered line box (default). Effect and script cuts inherit it
force-baselineCopy one style’s line box onto the family (largest span, or the file named by --line-box-from)
force-baseline-main-clusterSame, but that style is chosen from the core, not from effect or script cuts
safe-hheaAverage the typo/hhea values already stored in the files

--line-box-from PATH_OR_GLOB pins the reference font and implies force-baseline if you left the mode at auto. Single-font “families” skip force-baseline (nothing to unify).

Variable fonts

Default instance only. family, individual, and superfamily read and write the default instance the same way they treat a static font. They do not rewrite MVAR or HVAR. probe reads that same default instance and does not write.

What stays untouched

  • unitsPerEm
  • Glyph outlines and advances
  • Name tables (use FontNameID for those)
Exit codes. 0 done (including dry-run / nothing to change); 1 no font files; 2 no measurable fonts or bad args; 3 aborted at confirmation. probe only uses 0 / 1 / 2.
